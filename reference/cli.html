CLI reference ​

Visualization host for the 9aia tool suite

Usage: pavo [COMMAND]

Commands:
  drivers     List discovered tamias-driver-* executables that speak pavo
  views       List every <driver>:<view> ref with title/route
  chrome      Show the merged contribution slots
  view        Resolve a deep link and render it
  query       Raw query-op passthrough to a driver
  submit      Submit a form's field values (submit wire op)
  jobs        List the aggregated job feed (contributes.jobs providers)
  notifications  List the aggregated notification feed
  serve       Run the localhost HTTP bridge for the web host
  open        Hand off to pavo-tui (falls back to `view` text off-TTY)
  manifest    Print the machine-readable capability manifest
  schema      Print the verb schema
  help        Print this message or the help of the given subcommand(s)

Options:
  -h, --help     Print help
  -V, --version  Print version

--json is a per-subcommand flag on the listing/query verbs; view --format json is its machine-readable mode. Errors go to stderr; exit codes are CI-meaningful: 0 ok, 1 view/driver error, 2 usage.

drivers ​

sh
pavo drivers [--json]

Lists every discovered tamias-driver-* that speaks pavo — name, title, version, view count, renderer count, contributes summary. Discovery scans PATH and <tamias-home>/drivers/ ($TAMIAS_HOME → $XDG_DATA_HOME/tamias → ~/.local/share/tamias → ./.tamias).

views ​

sh
pavo views [--driver <name>] [--json]

Every view as a <driver>:<view> ref with title, route, and query names. --driver filters to one driver.

chrome ​

sh
pavo chrome [--json]

The merged contribution slots — all eight built-ins: navbar, dashboard, statusbar, routes, sidebar, headerActions, notifications, jobs — plus forward-compat extra slots, resolved across all drivers by priority. The notifications/jobs entries are provider display metadata; the feed data is what pavo jobs / pavo notifications aggregate.

view ​

sh
pavo view <driver>:<view> [--param k=v …] [--format FMT] [--json]

Resolves the deep link and renders the ViewNode tree plus bound data.

--formatOutput
text (default)summary of the tree + bound data
jsonraw ViewResult
dotgraph nodes → graphviz
mermaidgraph nodes → mermaid
<plugin>any format a renderer plugin claims (e.g. svg, ascii)

Renderer plugins take precedence per node: a plugin listing a built-in format name (text/dot/mermaid) in renderers[].surfaces.cli.formats overrides it for the kinds it claims; unclaimed nodes keep the built-in output. json is host-owned and never routed to plugins.

--param k=v merges caller params into every query binding; repeatable, values parse as JSON when possible. --json prints the machine-readable envelope.

query ​

sh
pavo query <driver> <query> [--param k=v …] [--json]

Raw query op passthrough — {"op":"query","query":"<query>", "params":{…}} — for probing a driver's data without a view.

submit ​

sh
pavo submit <driver>:<view> [--form <id>] [--param k=v …] [--json]

Sends the submit wire op — the form-interaction verb — with the given field values (--param key=value, repeatable; values parse as JSON when possible). --form picks a specific form node when the view carries several. Prints the driver's SubmitResult message and data; per-field validation errors exit 1 so CI can gate on them. --json dumps the full SubmitResult (including any updated view). Example: pavo submit config:edit --param key=myco.theme --param value=dark.

jobs ​

sh
pavo jobs [--json]

The aggregated job feed: {"op":"jobs"} fanned out to every driver whose manifest declares contributes.jobs, each item flattened with driver/driver_title attribution. Per-driver failures are skipped, never fatal. Item shape: JobItem — see Wire ops → Types.

notifications ​

sh
pavo notifications [--json]

The aggregated notification feed — same pattern as jobs over the notifications wire op and contributes.notifications providers. NotificationItem.read is display-only in v1 (no write path).

serve ​

sh
pavo serve [--port N]

The localhost HTTP bridge (127.0.0.1; --port 0 picks a free port). First stdout line is listening http://127.0.0.1:<port>. Endpoints and static serving: Serve the web surface.

open ​

sh
pavo open [<driver>:<view>]

Hands off to pavo-tui with the deep link, or the bare dashboard when no target is given. On a non-TTY it falls back to pavo view text output.

manifest / schema ​

sh
pavo manifest   # the CLI's own capability manifest (sibling convention)
pavo schema     # the verb schema

RenderModel — the canonical intermediate render output a view-kind renderer plugin emits for the render wire op.

Renderer plugins (drivers declaring renderers in their manifest) don’t ship surface code; they answer {"op":"render", …} with one of these tagged models and each surface maps it to native widgets:

variantCLITUIweb
rowsaligned tabletable rows<table>
svgraw markup[svg] hintv-html island
textlineslines<pre>
placeholder[component]box + detailnamed component

Wire shape (internally tagged on "type"):

{"type":"rows","headers":["id","label"],"aligns":["left","left"],
 "rows":[["a","Alpha"]]}

The set is deliberately small — plugins needing richer output use placeholder (web components) or svg (self-contained markup). Unknown type values must degrade gracefully on every surface (hosts treat them like placeholder).

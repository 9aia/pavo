pavo-protocol — the canonical wire contract for the pavo viz host.

Pure serde types, no I/O. Three contracts, all versioned (protocol/v1/ JSON Schemas mirror these types):

  • Driver manifest (manifest::DriverManifest) — what a tamias-driver-<type> executable answers to manifest: name, surfaces it contributes to, and the views it can render.
  • ViewNode IR (view_node::ViewNode) — the declarative UI tree a driver emits; renderers (CLI/TUI/web) interpret it.
  • Wire ops (wire::Request / wire::Response) — the ndjson JSON-RPC convention every sibling serve speaks: requests are {"op":"…", …}, responses are {"ok":true,"result":…} or {"ok":false,"error":"…"}.

Versioning policy: additive-only within v1 — new optional fields, new enum variants, and new ops may appear; existing fields and variant spellings never change meaning.

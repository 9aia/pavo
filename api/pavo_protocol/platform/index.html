Platform feeds — the item shapes behind the jobs and notifications wire ops.

Drivers that declare the matching contributes slots (crate::manifest::Contributes::jobs / crate::manifest::Contributes::notifications) are providers: the manifest entries are display metadata (label, icon, ordering) and the item data itself flows over the wire —

{"op":"jobs"}          → Vec<JobItem>
{"op":"notifications"}→ Vec<NotificationItem>

Both are optional capabilities: drivers without the feed answer ok:false (or an empty list) per the existing wire convention — hosts must tolerate either. The host knows which driver produced an item, so neither type carries driver attribution.

Timestamps are RFC 3339 strings (e.g. "2026-01-02T15:04:05Z") — chosen over unix epochs so payloads stay human-readable in transcripts and --json dumps. status/severity are free-form strings: drivers own their vocabularies ("queued", "running", "failed"; "info", "warning", "error", …) and hosts render them verbatim or degrade to neutral styling.

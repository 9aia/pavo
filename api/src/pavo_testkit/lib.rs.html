3//! pavo-testkit — conformance harness for pavo drivers and renderers.
4//!
5//! Three pieces, all built on `pavo-protocol`'s wire types:
6//!
7//! - [`fixture`] — [`fixture::FixtureDriver`], a builder that writes a
8//!   tempdir `tamias-driver-<name>` executable (a Python 3 script,
9//!   stdlib only) answering `manifest`/`views`/`view`/`query` over the
10//!   ndjson `serve` wire. Manifest, view specs, canned query results,
11//!   and failure modes (bad JSON line, `ok:false` errors, delayed
12//!   responses, mid-session exit) are all configurable — use it for
13//!   host/renderer tests without hand-writing shell fixtures.
14//! - [`conformance`] — [`conformance::check_driver`] runs the driver
15//!   contract suite over the wire and returns structured
16//!   [`conformance::Violation`]s instead of panicking.
17//! - [`record`] — capture a driver's ndjson session to a transcript
18//!   file ([`record::record_session`], [`record::save_transcript`])
19//!   and replay it deterministically as a new [`fixture::FixtureDriver`]
20//!   ([`record::replay_driver`]) — renderer tests without spawning
21//!   processes.
22//!
23//! [`wire`] exposes the raw [`wire::Session`] for tests that need to
24//! speak malformed lines or inspect transport errors directly.
25

3//! pavo-driver-kit — driver authoring for pavo view drivers.
4//!
5//! A `tamias-driver-<type>` executable is mostly boilerplate: the same
6//! ndjson `serve` loop, the same manifest/view struct literals, the
7//! same `ok:true`/`ok:false` plumbing — duplicated across every driver
8//! in the suite (myco, cuora, sepia, sturn, mimus, tamias, …). This
9//! crate absorbs the boilerplate so a driver's UI surface is **pure
10//! declaration**: build a [`manifest::Manifest`], answer ops with
11//! [`serve::serve_stdio`], and spend the rest of your time on data.
12//!
13//! The kit is deliberately small — four modules, no framework:
14//!
15//! - [`serve`] — the ndjson request/response loop every driver
16//!   re-implements (`{"op":"…"}` in, `{"ok":…}` out, one per line).
17//! - [`manifest`] — fluent builders for [`DriverManifest`],
18//!   [`ViewSpec`], [`QueryBinding`], and [`Contribution`] — including
19//!   the `deps` and cross-driver (`QueryBinding.driver`) declarations.
20//! - [`node`] — [`ViewNode`] constructors plus a [`node::Base`] builder
21//!   for the shared `id`/`title`/`query`/`description`/`props` fields.
22//! - [`platform`] — [`JobItem`] / [`NotificationItem`] constructors
23//!   for the `jobs`/`notifications` feed ops.
24//! - [`surface`] — the surface-driver layer: an engine's **ops
25//!   manifest** (`ops` verb / `cli.*` wire queries) rendered onto real
26//!   surfaces — a generated clap CLI (feature `cli`), MCP tools over
27//!   stdio (feature `mcp`), and the spawned-driver [`surface::client`]
28//!   both standalone binaries (`tamias-driver-cli`, `-mcp`) are built
29//!   on. Engine drivers may embed the same surfaces behind their own
30//!   features — optional, never required.
31//!
32//! All types are `pavo-protocol`'s — the kit adds constructors and
33//! the loop, never a parallel type hierarchy. Anything the kit doesn't
34//! cover, drivers write against `pavo-protocol` directly.
35//!
36//! # Minimal driver
37//!
38//! ```no_run
39//! use pavo_driver_kit as kit;
40//! use pavo_protocol::wire::{Request, Response};
41//!
42//! fn main() {
43//!     let manifest = kit::Manifest::new("demo", "Demo")
44//!         .view(kit::view("board", "Board", "/demo/board",
45//!             kit::column(kit::base().title("Board"), vec![
46//!                 kit::markdown(kit::base(), "hello"),
47//!             ])))
48//!         .build();
49//!     kit::serve_stdio(|req| match req {
50//!         Request::Manifest => Response::ok_typed(&manifest),
51//!         Request::Views => Response::ok(serde_json::json!([])),
52//!         _ => Response::err("unsupported op"),
53//!     })
54//!     .ok();
55//! }
56//! ```
57//!
58//! See `examples/drivers/` for full drivers; `crates/pavo-driver-config`
59//! is the first-party Rust driver (it predates the kit and shows the
60//! hand-rolled equivalent).

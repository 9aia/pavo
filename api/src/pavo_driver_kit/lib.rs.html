3//! pavo-driver-kit — driver authoring for pavo view drivers.
4//!
5//! A `tamias-driver-<type>` executable is mostly boilerplate: the same
6//! ndjson `serve` loop, the same manifest/view struct literals, the
7//! same `ok:true`/`ok:false` plumbing — duplicated across every driver
8//! in the suite (myco, cuora, sepia, sturn, mimus, tamias, …). This
9//! crate absorbs the boilerplate so a driver's UI surface is **pure
10//! declaration**: build a [`manifest::Manifest`], answer ops with
11//! [`serve::serve_stdio`], and spend the rest of your time on data.
12//!
13//! The kit is deliberately small — four modules, no framework:
14//!
15//! - [`serve`] — the ndjson request/response loop every driver
16//!   re-implements (`{"op":"…"}` in, `{"ok":…}` out, one per line).
17//! - [`manifest`] — fluent builders for [`DriverManifest`],
18//!   [`ViewSpec`], [`QueryBinding`], and [`Contribution`] — including
19//!   the `deps` and cross-driver (`QueryBinding.driver`) declarations.
20//! - [`node`] — [`ViewNode`] constructors plus a [`node::Base`] builder
21//!   for the shared `id`/`title`/`query`/`description`/`props` fields.
22//! - [`platform`] — [`JobItem`] / [`NotificationItem`] constructors
23//!   for the `jobs`/`notifications` feed ops.
24//!
25//! All types are `pavo-protocol`'s — the kit adds constructors and
26//! the loop, never a parallel type hierarchy. Anything the kit doesn't
27//! cover, drivers write against `pavo-protocol` directly.
28//!
29//! # Minimal driver
30//!
31//! ```no_run
32//! use pavo_driver_kit as kit;
33//! use pavo_protocol::wire::{Request, Response};
34//!
35//! fn main() {
36//!     let manifest = kit::Manifest::new("demo", "Demo")
37//!         .view(kit::view("board", "Board", "/demo/board",
38//!             kit::column(kit::base().title("Board"), vec![
39//!                 kit::markdown(kit::base(), "hello"),
40//!             ])))
41//!         .build();
42//!     kit::serve_stdio(|req| match req {
43//!         Request::Manifest => Response::ok_typed(&manifest),
44//!         Request::Views => Response::ok(serde_json::json!([])),
45//!         _ => Response::err("unsupported op"),
46//!     })
47//!     .ok();
48//! }
49//! ```
50//!
51//! See `examples/drivers/` for full drivers; `crates/pavo-driver-config`
52//! is the first-party Rust driver (it predates the kit and shows the
53//! hand-rolled equivalent).

Driver conformance — check_driver runs the pavo wire contract suite against a tamias-driver-* executable and returns structured Violations rather than panicking.

The suite (all over <driver> serve, one persistent session):

  1. {"op":"manifest"} → parses as DriverManifest and advertises pavo ("serve" in verbs or "pavo" in capabilities).
  2. {"op":"views"} → parses as Vec<ViewSummary> whose id set matches the manifest’s declared views.
  3. {"op":"view","view":<id>"} for every declared view → parses as ViewResult, echoes the requested view id, and its data map carries every declared query binding.
  4. {"op":"query","query":<name>"} for every declared binding → parses as QueryResult.
  5. Malformed requests — an unknown op and a non-JSON line — must both get an ok:false Response.
  6. The process must still answer after all of the above (session liveness across multiple requests).

Transport failures (timeout, EOF, unparseable response lines) become violations on the check that hit them; the suite keeps going so one broken op doesn’t hide the rest.

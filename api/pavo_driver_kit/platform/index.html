Platform feed constructors — JobItem and NotificationItem, the payloads behind the jobs and notifications wire ops.

A driver becomes a feed provider by declaring the matching contributes slot (crate::manifest::Manifest::jobs / crate::manifest::Manifest::notifications); the ops then carry item lists. Both are optional capabilities — drivers without a feed answer ok:false (or []), which hosts read as “no feed”.

let j = kit::job("build-1", "Build pavo", "running");
let mut n = kit::notification("n-1", "Build finished");
n.severity = Some("info".to_string());
n.read = true;

Functions§

job
One JobItem — id/title/status are the required trio (status is a free-form driver-owned string: "queued", "running", "done", "failed", …). detail, route, updated_at (RFC 3339), and extra are public fields.
notification
One NotificationItem — id/title required; body, severity (free-form: "info"/"warning"/"error"/…), route, created_at (RFC 3339), read, and extra are public fields.

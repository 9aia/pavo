Config resolution — the “common config API” half of tamias-driver-config.

The driver answers namespaced queries (get myco.theme, resolve, sources) over a layered config tree; callers never read the files themselves. Layers, lowest → highest precedence:

  1. defaults — built-in (theme=dark, statusbar=true, refresh_ms=5000).
  2. global — $XDG_CONFIG_HOME/pavo/pavo.{toml,json} or ~/.config/pavo/pavo.{toml,json}.
  3. project — every pavo.toml/pavo.json found walking up from the cwd (filesystem root → cwd; nearer files win per-key, nested tables merge recursively).
  4. explicit — --config <path> (manual serve only; pavo’s spawned serve can’t pass argv) or $PAVO_CONFIG. One file, highest file-layer precedence.
  5. env — PAVO_CONFIG_* overrides for scalar keys: PAVO_CONFIG_THEME=light → theme; __ separates dotted segments (PAVO_CONFIG_MYCO__THEME → myco.theme), single _ stays literal (PAVO_CONFIG_REFRESH_MS → refresh_ms). Values parse as JSON when possible, else strings.

set writes back to the project-level file: the explicit path when --config/PAVO_CONFIG named one, else the nearest project file found, else a fresh ./pavo.toml in the cwd. Writes preserve TOML formatting/comments via toml_edit; JSON is rewritten pretty-printed.

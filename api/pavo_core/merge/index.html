Contribution merge — fold every discovered driver’s pavo_protocol::Contributes into one Chrome description the renderers lay out.

§Ordering policy (deterministic)

Within each slot, entries sort by priority ascending — lower wins — per pavo_protocol::Contribution’s contract (“lower sorts first”). Ties break by driver kind ascending, then contribution id ascending. The protocol doc says ties break by “driver discovery order”; we substitute driver name because PATH order is environment-dependent and nondeterministic across machines — name order is stable and gives the same “one winner” guarantee. Same-slot duplicate ids from different drivers can’t collide: every id is namespaced <driver>:<id> at merge time.

extra slots (unknown to this host version) merge the same way and pass through untouched — forward compatibility per the protocol’s degrade-gracefully rule.

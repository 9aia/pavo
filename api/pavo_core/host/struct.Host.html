pub struct Host { /* private fields */ }

The pavo host — discovered drivers, lazy serve clients, merged chrome, view cache. Send + Sync: all mutable state is behind mutexes, and the only lock held across a driver round-trip is that driver’s own client lock.

pub fn client(&self, kind: &str) -> Result<Arc<Mutex<DriverClient>>, PavoError>

The live serve client for kind, spawning on first use.

The returned Arc<Mutex<DriverClient>> is the per-driver serialization point — Host::with_client locks it for you. The spawn happens under the clients-map lock so two threads can’t double-spawn; the lock is released before any request.

§Errors

PavoError::UnknownDriver / PavoError::MissingDriver / spawn errors.

pub fn resolve_view( &self, target: &str, params: Params, ) -> Result<ResolvedView, PavoError>

Resolve a deep link to a rendered view.

target is "<driver>:<view>" (e.g. "myco:board"); a bare "<driver>" resolves to the driver’s first declared view. params are caller-supplied view params passed to the driver’s view op. Results are cached per driver:view + params.

§Errors

PavoError::BadViewRef on unparseable targets, PavoError::UnknownDriver/PavoError::UnknownView for missing pieces, client errors propagate.

pub fn submit( &self, target: &str, form: Option<&str>, values: Params, ) -> Result<SubmitResult, PavoError>

{"op":"submit"} — submit a form’s field values to the driver that owns target ("<driver>:<view>", bare "<driver>" = its first view, same as Host::resolve_view). form optionally names the form node’s id when the view carries several forms.

On success every cached result for that driver:view is invalidated — submits mutate driver state, so the next resolve_view must re-fetch (a returned SubmitResult::view is not inserted into the cache; it belongs to the submitting renderer).

§Errors

PavoError::BadViewRef / PavoError::UnknownDriver / PavoError::UnknownView for bad targets; ok:false driver answers (validation failures included — check SubmitResult::errors on Ok) propagate as PavoError::Driver.

pub fn render_view_plugins( &self, resolved: &ResolvedView, surface: &str, format: Option<&str>, ) -> HashMap<String, RenderModel>

Render every plugin-claimed node in a resolved view for surface — one render op per node, keyed by the node’s crate::renderers::PluginNode::path. Nodes whose plugin call fails are skipped (the caller falls back to built-in rendering for that node — a broken plugin degrades one node, never the whole view).

format is the surface’s format hint (CLI --format); pass None for the surface default.

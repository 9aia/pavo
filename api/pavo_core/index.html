pavo-core — host core: tamias driver discovery, contribution merge, per-driver wire clients, ViewNode IR helpers, and the view-model cache.

The host’s job (per P-003): find tamias-driver-* executables that speak pavo (a manifest verb answering pavo_protocol::DriverManifest, or capabilities advertising it), merge their contributes slots into one chrome description, and resolve <driver>:<view> deep links into [pavo_protocol::ViewResult]s by speaking the ndjson wire ({"op":"…"} → {"ok":…}) over each driver’s serve verb.

Everything here is sync and std-only — no async runtime, no renderer deps. Renderers (CLI/TUI/web) consume Host’s output; they never see driver processes.

Module map:

  • discovery — scan PATH + <tamias-home>/drivers/ for pavo-capable tamias-driver-* executables.
  • client — client::DriverClient, one spawned serve process per driver, request/response with timeout + one restart.
  • merge — fold every driver’s contributes into a single merge::Chrome (navbar/dashboard/statusbar/routes/sidebar/ headerActions/notifications/jobs + extra).
  • deps — topological ordering over DriverManifest.deps (requires/optional); host::Host keeps drivers in dep order and quarantines offenders.
  • host — host::Host, the composition root renderers use: discovery → manifests → clients → views/routes/chrome.
  • viewnode — walk/evaluate helpers over the ViewNode IR (find_nodes, collect_queries, KV degradation).
  • renderers — renderer-plugin registry: manifest renderers[] declarations → kind claims, conflict resolution, render ops.
  • paths — <tamias-home> resolution ($TAMIAS_HOME → $XDG_DATA_HOME/tamias → ~/.local/share/tamias → ./.tamias).
  • cache — small TTL cache for view models.
  • error — the crate’s error::PavoError type.

Modules§

cache
A small TTL cache — Mutex<HashMap> + Instant expiries, std-only.
client
The serve client — one spawned tamias-driver-<type> serve process per driver, speaking the pavo ndjson wire: one JSON pavo_protocol::Request per line on stdin, one pavo_protocol::Response per line on stdout.
deps
Driver dependency ordering — topological sort over the pavo_protocol::DriverDeps declarations manifests carry.
discovery
Driver discovery — find tamias-driver-* executables that speak pavo, on PATH and in <tamias-home>/drivers/.
error
Error type for pavo-core — one enum covering discovery, the serve client, and host-level resolution failures.
host
Host — the composition root renderers talk to.
merge
Contribution merge — fold every discovered driver’s pavo_protocol::Contributes into one Chrome description the renderers lay out.
paths
Tamias home resolution — copied from tamias-driver (the helpers are tiny and pavo must not depend on tamias crates; the layout is the shared contract, not the code).
renderers
Renderer registry — collect renderers declarations from every discovered driver’s manifest into a kind → driver lookup, and find the plugin-rendered nodes inside a resolved view tree.
viewnode
ViewNode IR helpers — the walk/evaluate utilities renderers need.

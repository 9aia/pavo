Module client 

Source
Expand description

The serve client — one spawned tamias-driver-<type> serve process per driver, speaking the pavo ndjson wire: one JSON pavo_protocol::Request per line on stdin, one pavo_protocol::Response per line on stdout.

Transport shape mirrors tamias-serve’s loop (and every sibling serve): requests {"op":"…", …} → {"ok":true,"result":…} / {"ok":false,"error":"…"}.

Reliability policy:

  • Timeout — every request waits at most ClientConfig::timeout (default 10s) for its response line.
  • Restart + retry — transport failures only (io error, EOF, timeout, malformed response) kill the child and retry the request once on a fresh process, up to ClientConfig::max_restarts extra attempts. A driver that answers ok:false, or returns a result that doesn’t deserialize, is not retried — it’s alive and complaining.
  • Clean shutdown — DriverClient’s Drop kills and reaps the child; stderr is drained on a thread (never blocks the driver) with a bounded tail kept for diagnostics.

Sync only — a stdout reader thread feeds an mpsc channel so recv_timeout gives us the request timeout without an async runtime. DriverClient is !Sync-ish by design: requests are &mut self, one in flight at a time (the wire is request/response ordered anyway).

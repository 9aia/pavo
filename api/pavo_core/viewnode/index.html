ViewNode IR helpers — the walk/evaluate utilities renderers need.

The IR is a tree of ViewNodes; containers (panel, row, column) nest children, everything else is a leaf. These helpers give renderers three things without re-implementing the traversal:

  • walk / find_nodes / children / kind_of — tree traversal and kind inspection.
  • collect_queries — every NodeBase::query binding name in a tree, so a renderer/host knows which view-model keys a tree consumes.
  • KV degradation — to_kv_fallback turns any known ViewNode into a KvNode; node_kind_json + kv_fallback_json do the same for a raw serde_json::Value whose kind this host doesn’t know (the protocol’s forward-compat rule: unknown kinds degrade to generic KV, never fail).

Functions§

children
A node’s children — panel/row/column nest Vec<ViewNode>; every other kind is a leaf and yields an empty slice.
collect_queries
Every query binding name referenced by NodeBase::query anywhere in the tree — the set of view-model keys the tree consumes. Sorted (BTreeSet) for deterministic output.
find_nodes
All nodes in the tree whose kind_of equals kind, pre-order.
kind_of
The kind discriminator of a node, as the wire spells it ("panel", "table", …).
kv_fallback_json
Degrade a raw node JSON object to {"kind":"kv", …} — same rule as to_kv_fallback but for trees that haven’t (or can’t) deserialize into ViewNode because their kind is unknown to this host version.
node_kind_json
The kind string of a raw node JSON — None when absent or not a string. Renderers call this before deserializing so unknown kinds can route to kv_fallback_json instead of failing.
to_kv_fallback
Degrade any known ViewNode to a KvNode — the universal fallback renderers use for kinds they don’t implement (and the shape kv_fallback_json produces for unknown wire kinds).
walk
Depth-first pre-order walk over the whole tree — f sees every node exactly once, root first.

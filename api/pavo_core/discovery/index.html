Driver discovery — find tamias-driver-* executables that speak pavo, on PATH and in <tamias-home>/drivers/.

Scan order mirrors tamias-driver::discovered_drivers: every PATH dir in order, then the drivers dir; the first executable claiming a <type> wins, results sorted by kind for determinism.

A candidate is pavo-capable when either probe advertises it:

  1. tamias-driver-<type> manifest exits 0 with a body that parses as pavo_protocol::DriverManifest and either lists "serve" in verbs or "pavo" in capabilities (the manifest’s own capability-negotiation rule). The manifest is kept eagerly — pavo can list routes/contributions without spawning serve.
  2. Failing that, tamias-driver-<type> capabilities exits 0 with JSON whose capabilities/verbs arrays mention "pavo" or "serve". No manifest is available yet — DriverInfo::manifest is None and Host fetches one lazily over the serve wire’s manifest op.

Candidates that error, time out (DiscoveryOptions::probe_timeout per probe), or answer non-pavo JSON are skipped — discovery never fails wholesale because one driver is broken.

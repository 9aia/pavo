pavo_tui

Module model 

Source
Expand description

ViewNode → flat render model for the ratatui canvas.

build_view walks a resolved view’s node tree (as raw JSON, same as pavo-cli’s render.rs — the protocol’s forward-compat rule holds end-to-end: an unknown kind degrades through kv_fallback_json to a key/value listing, never an error) and produces plain rows the renderer styles. Selectable rows carry an index into Model::selections; the detail pane renders the matching Selection.

Traversal semantics deliberately mirror pavo-cli/src/render.rs: containers (panel/row/column) print their title then children indented two spaces per level (row does not attempt side-by-side layout), inline rows/items/pairs win over query-bound data, and a bound payload of {"error": "…"} renders as an error row instead of data.

build_dashboard and build_note synthesize models for the chrome pseudo-views (contribution listing, error/info panes) that aren’t driver views at all.

The ratatui surface: panes, key handling, drawing.

Layout (per the pavo design note):

┌ tabs: dashboard · navbar contributions ──────────────── [?] help ┐
│ drivers │ view canvas (ViewNode IR)      │ detail (selection)  │
│  20%    │                               │       30%           │
├────────┴───────────────────────────────┴───────────────────────┤
│ status — driver @ view · message              statusbar slots  │
└───────────────────────────────────────────────────────────────┘

All Host work happens on the [worker] thread; this module only draws model output and forwards Cmds. Panes: Rail (drivers) → Canvas (current view/dashboard/note) → Detail (selected row’s fields). Tab/←/→ cycle focus.

Platform chrome slots (sidebar, header_actions, notifications, jobs) have no dedicated TUI chrome — no sidebar pane, no action bar, no feed polling — so they render as contribution sections on the dashboard (see model::build_dashboard).

pavo — the CLI surface of the viz host.

Verbs:

  • drivers — list discovered tamias-driver-* executables that speak pavo (manifest version, view count, contributes summary).
  • views [--driver <name>] — every view as a <driver>:<view> ref with title/route.
  • chrome — the merged contribution slots (navbar/dashboard/ statusbar/routes/sidebar/headerActions/notifications/jobs + forward-compat extras).
  • view <driver>:<view> [--param k=v …] [--format …] — resolve a deep link and render it: text (default) summarizes the ViewNode tree + bound data, json dumps the raw [ViewResult], dot/mermaid emit the view’s graph nodes.
  • query <driver> <query> [--param k=v …] — raw query op passthrough.
  • submit <driver>:<view> [--form <id>] --param k=v … — the submit wire op: send a form’s field values to its driver and print the SubmitResult (message/errors/data; --json dumps the full payload including any updated view).
  • jobs / notifications — the aggregated platform feeds: every provider driver’s jobs/notifications wire op, tagged with its driver (--json dumps the flattened rows).
  • serve [--port N] — the localhost HTTP bridge for the web host: /api/* JSON endpoints over the same [Host] plus static serving of the Nuxt build (web/.output/public). First stdout line is listening http://127.0.0.1:<port>.
  • open [<driver>:<view>] — hand off to pavo-tui (the ratatui surface) with the deep link, or the bare dashboard when no target is given. On a non-TTY it falls back to pavo view text output for the given target.
  • manifest / schema — the CLI’s own capability manifest and verb schema (sibling convention: tamias/kuda).

--json is a per-subcommand flag (sibling convention) on the listing/query verbs; view --format json is its machine-readable mode. Errors go to stderr; exit codes are CI-meaningful: 0 ok, 1 view/driver error, 2 usage (bad --param, malformed view ref, bad format — clap reports the last itself).

Discovery is environment-driven like pavo-core’s [Host::discover]: drivers are found on PATH and under $TAMIAS_HOME/drivers — set PATH/TAMIAS_HOME to point the CLI at fixture drivers (integration tests do exactly this).

BUILTIN_FORMATS 🔒
The built-in view --format values — all but json can be claimed by renderer plugins (renderers[].surfaces.cli.formats, empty = wildcard); a plugin claim substitutes its RenderModel for the claimed nodes and the built-in covers the rest. json is the raw ViewResult dump — host-owned, never routed to plugins.

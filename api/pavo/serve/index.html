pavo serve — the localhost HTTP bridge: pavo-core’s [Host] on one side, the Nuxt web app (or any JSON client) on the other.

Hand-rolled HTTP/1.1 over std::net::TcpListener, thread-per- connection, std-only (see crate::http for the wire bits). One [Host] is shared across threads behind an Arc — it is Sync: lazy manifest fetches, client spawns, and the view cache are internally locked, and each driver’s serve client carries its own mutex so requests to different drivers run in parallel while same-driver requests stay serialized on the wire.

Routes:

  • GET /api/health → {ok:true}
  • GET /api/drivers → per-driver manifest summary
  • GET /api/views → every <driver>:<view> entry
  • GET /api/chrome → merged chrome slots (navbar/dashboard/ statusbar/routes/sidebar/headerActions/notifications/jobs + forward-compat extras)
  • GET /api/jobs → the aggregated job feed (contributes.jobs providers’ jobs op, items tagged with their driver)
  • GET /api/notifications → the aggregated notification feed
  • POST /api/call?driver=<kind> → cross-driver wire proxy: the JSON body is a wire Request forwarded verbatim to that driver’s serve; its result comes back in the envelope
  • GET /api/view?ref=<driver>:<view> (+ param.<k>=<v>) → ViewResult
  • GET /api/raw?ref=… → same as /api/view
  • GET /api/query?driver=<d>&query=<q> (+ param.<k>=<v>) → QueryResult
  • GET /api/submit?ref=<d>:<v>[&form=<id>][&values=<json>] → SubmitResult
  • GET /api/renderers → the renderer-plugin registry (kind claims)
  • GET /api/render?kind=<k>&node=<json>&data=<json>&surface=<s>[&format=<f>] → RenderModel — routes to the claiming driver’s render op
  • GET /* → static files from the Nuxt output (web/.output/public, web/dist, or $PAVO_WEB_DIR), else a built-in landing page. /view/<ref> deep links take params as path k=v segments (/view/demo:board/id=T-1) or param.*/bare query keys — the Nuxt page speaks the same grammar (see web/app/utils/view-link.ts).

All /api/* responses use the {"ok":…,"result"/"error"} envelope with Access-Control-Allow-Origin: * — this is a localhost dev tool, not a hardened server. GET/HEAD everywhere except POST /api/call (the wire proxy needs a body).

api_call 🔒
POST /api/call?driver=<kind> — the cross-driver escape hatch. The request body is a wire WireRequest JSON object ({"op":"query",…}, {"op":"jobs"}, …) forwarded verbatim to that driver’s serve session; the driver’s result payload comes back under the usual {"ok":true,"result":…} envelope. The driver name is validated by [Host::client] — unknown kinds 404, dep-quarantined drivers surface their [PavoError::Deps].

parse_view_path 🔒
Split a /view/ path remainder into (ref, params) — the first /-separated segment is the driver:view ref, each later segment is key=value (a bare key means an empty value). Query keys are params too: bare ?k=v first, then param.* on top, so query wins over path and param.* wins over bare on collision — the same grammar the Nuxt page normalizes into param.<k>=<v>.
resolve_static 🔒
Resolve path under root safely — rejects .. escapes and non-UTF8 tricks. Returns the file path or None.
route 🔒
Route one request → (response, close_after). close_after is set for HEAD and for errors where keep-alive state is uncertain.
run
Run the bridge until killed. Binds 127.0.0.1:port; port 0 picks a free port. The first stdout line is always listening http://127.0.0.1:<port> so wrappers/tests can learn it.
serve 🔒
The accept loop, split from run so tests can bind their own listener (and learn the port) without parsing stdout.
